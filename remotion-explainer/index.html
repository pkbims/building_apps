Round 1

1A video is a function of the frame number

The one idea everything else follows from.

Remotion is a React library. You write a component; Remotion calls it once per frame with a single number — which frame is this? — and takes a screenshot of whatever the component drew. A 60-second video at 30 fps is 1,800 screenshots stitched together.

import { useCurrentFrame, useVideoConfig, AbsoluteFill } from "remotion";

export const Hello = () => {
  const frame = useCurrentFrame();          // 0, 1, 2, … up to durationInFrames - 1
  const { fps, width } = useVideoConfig();   // 30, 1920 — set on the Composition
  const seconds = frame / fps;
  return (
    <AbsoluteFill style={{ background: "#111", color: "#fff", fontSize: 80,
                            justifyContent: "center", alignItems: "center" }}>
      {seconds.toFixed(2)} s
    </AbsoluteFill>
  );
};

Nothing in that component moves on its own. It is a pure function: same frame in, same picture out. That is a constraint, and it is the reason Remotion works at all:

  • Frames can be rendered in any order, on any number of machines. Frame 1,200 does not depend on frame 1,199 having been drawn first. Remotion opens several headless Chrome tabs and hands each one a slice of the frame range.
  • Previews are exact. Scrubbing the Studio timeline to frame 812 renders frame 812 — the same pixels the final export will contain.
  • The edit is data. Because the picture is decided by inputs (frame + props), a cut, a layout, a zoom is a value in a JSON object, not a gesture on a timeline. That is what makes it something Claude Code can write.
The gotcha this creates. Anything that animates by wall-clock time — CSS transition, CSS @keyframes, setTimeout, a GIF, a <video autoplay> — is invisible to Remotion, because the renderer freezes time and asks "what does frame N look like?". Every motion must be computed from useCurrentFrame(). This is the mistake every newcomer makes once.

2From frames to an mp4

Why renders are slow, and why it doesn't matter as much as it sounds.

your React code ──bundle (webpack)──▶ a web page that can show any frame
                                              │
                        headless Chrome × N tabs, each told "render frames a…b"
                                              │  screenshot per frame (JPEG or PNG)
                                              ▼
                                   ffmpeg encodes frames + audio ──▶ out/video.mp4

Three consequences worth knowing:

  • Render time ≈ frames ÷ (tabs × frames-per-second-per-tab). A screenshot of a 1080p page with two videos composited in it takes tens of milliseconds; a 20-minute video is 36,000 frames. On a laptop expect several minutes, sometimes more. The Studio preview, by contrast, is instant, because it renders only the frame under the playhead.
  • Video inside video is the expensive part. When your composition contains an <OffthreadVideo> (the webcam or display recording), Remotion has to extract the exact frame of that mp4 for every output frame. It does this with ffmpeg in a separate process ("off thread") so Chrome does not stall. This is why the Recorder's export is slower than a pure-graphics video of the same length.
  • Audio is mixed separately. Chrome screenshots have no sound. Remotion collects every <Audio>/<Video> element's timing and volume and mixes the track with ffmpeg at the end.

The render commands you'll actually use here: bunx remotion render <composition-id> writes to out/; bun run dev starts the Studio on port 3000. Remotion also ships a Lambda renderer that splits the frame range across many AWS functions — not needed for this series, but it is the same mechanism scaled out.

3The building blocks

Seven things cover 90% of what you'll read in video/remotion/.

ThingWhat it isWhy it exists
<Composition>A named, renderable video: id, component, fps, width, height, durationInFrames, defaultProps, and optionally a zod schema. Declared in Root.tsx.The renderer and the Studio need a list of "things you can export". Each Recorder project (public/app_1/) becomes one Composition.
useCurrentFrame()The frame number, relative to the nearest <Sequence>.The only clock. Everything animates from it.
useVideoConfig(){ fps, width, height, durationInFrames } of the current Composition.So components can convert seconds↔frames and size themselves without hardcoding 1920×1080.
<Sequence from durationInFrames>Shifts time for its children: inside it, useCurrentFrame() starts at 0 at frame from, and the children are not mounted outside the window.Lets you build a scene as if it started at 0, then place it anywhere. The Recorder's Main.tsx is a list of Sequences, one per scene.
<AbsoluteFill>A div with position:absolute; inset:0 and flex centering.Layers. Stack several and you have a compositor: video at the bottom, captions above, a graphic above that.
<OffthreadVideo>, <Audio>, <Img>, staticFile()Media elements that are frame-accurate during render. staticFile("app_1/webcam123.mp4") resolves to public/.A plain <video> tag plays by wall-clock; these seek to the exact frame. startFrom/endAt on them are how trims happen.
interpolate(), spring(), EasingNumber → number helpers. See the next section.Turn "frame 40" into "opacity 0.6", which is all an animation is.

Everything else — @remotion/captions, @remotion/transitions, @remotion/google-fonts, @remotion/shapes — is a library built from these seven. Fonts deserve one note: because a screenshot taken before the font loaded would be wrong, Remotion has delayRender()/continueRender() to hold a frame until an async thing is ready. config/fonts.ts in the Recorder uses exactly that.

4How animation works

Two functions. Every zoom, slide, fade and bounce in the Recorder is one of them.

interpolate — a straight line between two ranges

// frame 0 → opacity 0, frame 30 → opacity 1, and stay there afterwards
const opacity = interpolate(frame, [0, 30], [0, 1], {
  extrapolateLeft: "clamp", extrapolateRight: "clamp",
});

// multiple stops: fade in, hold, fade out
const o = interpolate(frame, [0, 20, 100, 120], [0, 1, 1, 0], { extrapolateRight: "clamp" });

It maps an input range to an output range, piecewise-linear. The clamp options matter: without them, frame 45 gives opacity 1.5. Pass an easing (Easing.inOut(Easing.cubic)) to bend the line. This is the tool for anything with a known start and end time — a fade, a progress bar, a layout tween.

spring — physics with no fixed end time

const scale = spring({ frame, fps, config: { damping: 200 } });        // 0 → 1, smooth, no overshoot
const pop   = spring({ frame, fps, config: { damping: 8, stiffness: 100 } }); // 0 → 1 with bounce
const delayed = spring({ frame: frame - 15, fps });                      // starts 15 frames later

A damped spring simulation that returns a value from 0 approaching 1. You don't choose a duration; you choose mass/stiffness/damping and the motion feels natural because it is the same maths as a real object settling. This is why the Recorder's captions "pop" into place — SingleCaption.tsx runs a spring that starts at each word's timestamp.

Combining them — a zoom, which is what you want

// Zoom into a region of the screen recording between two frames.
const ZoomedDisplay = ({ src, zoom }) => {
  const frame = useCurrentFrame();
  const { fps } = useVideoConfig();
  // zoom = { from: 120, to: 300, x: 0.7, y: 0.3, scale: 2 }  ← this is data Claude can write
  const inP  = spring({ frame: frame - zoom.from, fps, config: { damping: 200 } });
  const outP = spring({ frame: frame - zoom.to,   fps, config: { damping: 200 } });
  const p = inP - outP;                          // 0 → 1 while zoomed, back to 0 after
  const scale = interpolate(p, [0, 1], [1, zoom.scale]);
  return (
    <AbsoluteFill style={{ overflow: "hidden" }}>
      <OffthreadVideo src={src} style={{
        transform: `scale(${scale})`,
        transformOrigin: `${zoom.x * 100}% ${zoom.y * 100}%`,
      }} />
    </AbsoluteFill>
  );
};

Read it as: two springs, one triggered at the start frame and one at the end, subtracted to make a plateau; the plateau drives a CSS transform. That is the whole trick. Screen Studio's auto-zoom is this plus a heuristic for choosing x, y, from, to from cursor clicks — in our pipeline the heuristic is Claude reading the transcript ("now I open the migrations folder") and writing the zoom object.

Transitions between scenes

The Recorder does not use a transitions library; it does it by hand and the code is short. animations/scene-transitions.ts decides that a video scene following a video scene slides by 0 (no move) and anything else slides in from canvasWidth; interpolate-layout.ts tweens left/top/width/height/borderRadius/opacity between two layouts with interpolate. The webcam gliding from bottom-right to full-screen is that function called with the two layouts and a progress value from a spring. SCENE_TRANSITION_DURATION = 15 frames, in config/transitions.ts.

5The Recorder, mapped to files in video/

What the template adds on top of bare Remotion. Paths are real; open them.

record (localhost:4000, src/)  ──▶  public/<project>/webcam<ts>.mp4 + display<ts>.mp4
                                          │  "Use this take" → whisper.cpp → subs<ts>.json
                                          ▼

                     builds scenesAndMetadata (from-frame, layout, captions per scene)
                                          ▼
Root.tsx  ──▶  <Composition id="<project>" schema={videoConf}>  ← props = the edit
                                          ▼

                                          ▼
                     bunx remotion render <project>  ──▶  out/<project>.mp4 (+ .srt)
FileRole
src/The recording UI. A Vite app that uses the browser's getUserMedia/getDisplayMedia, records each stream to WebM, and posts them to the little Express server in scripts/server/, which converts to mp4 and kicks off transcription. Two streams, two files, same timestamp in the name — that is the "always record separately" rule, enforced by the tool.
config/scenes.tsThe zod schema of a video. A scene is one of videoscene (a take: webcamPosition, startOffset/endOffset in frames, newChapter, bRolls, music), title, tableofcontents, endcard, recorder. Because it is a zod schema, the Studio renders a form for it in the right sidebar — that is where you "edit" without touching code, and it saves back into Root.tsx's defaultProps.
config/layout.ts, remotion/layout/Canvas is landscape 1920×1080 or square 1080×1080. get-layout.ts decides, per scene, where the webcam and display rectangles go: display present → display fills up to 77% of the width, webcam in the chosen corner; no display → webcam fills the canvas. This is the automatic "face / screen+face" switch.
remotion/animations/The interpolate/spring code from section 4: layout tweens, scene slides, caption fades, webcam moves.
remotion/captions/Reads subs<ts>.json (word-level Caption[]), groups words into lines that fit the box, renders them with a spring per word. Also emits the .srt for YouTube. config/autocorrect.ts is a hook to fix words Whisper mis-hears — you will add "Postgres", "FastAPI", "Compose" there.
config/fps.ts, config/fonts.ts, config/themes.ts30 fps. Inter + Roboto Mono via @remotion/google-fonts. Light/dark theme colours. Restyling the whole series is these three files.
scripts/captions/, config/whisper.tsInstalls whisper.cpp 1.7.2, downloads medium.en, runs it with tokenLevelTimestamps: true, converts the output to Remotion's caption JSON.

What is deliberately not here: any zoom, any cursor effect, any graphics beyond title/endcard/b-roll image. Those are yours to add as components — section 7.

6What is AI here, and what is not

Shorter list than the marketing suggests.

ComponentAI?What it actually is
Rendering, layout, animation, transitionsNoDeterministic code. Same inputs, same pixels. There is no model anywhere in the render path, which is why renders are reproducible and can go in CI.
Captions / transcriptionYes — the only oneWhisper, OpenAI's open-weights speech-to-text model, run through whisper.cpp (a C++ port, compiled here with Metal so it uses the Mac's GPU). Model file: ggml-medium.en.bin, 1.5 GB, English-only, in video/whisper.cpp/. Runs entirely on your machine; nothing is uploaded. Output is per-token timestamps, which Remotion converts to word-level captions. "medium.en" is the accuracy/speed middle; large-v3 is more accurate and ~2× slower, small.en is faster and worse with technical terms. Changed in one line in config/whisper.ts.
Remotion "Agent Skills" / the Claude Code pluginNot a modelMarkdown instruction files that teach a coding agent Remotion's rules (the frame-based animation rule from section 1, how to structure compositions, caption best practices, how to fetch their docs as markdown). They contain no weights; they make Claude better at writing Remotion code. Installed in this Claude Code as remotion@remotion.
Remotion Studio's "AI" featuresOptional, offStudio can prompt a hosted model to edit a composition. remotion.config.ts disables it here; Claude Code in the terminal is the agent for this series.
Claude Code (this pipeline)YesWrites the scene list, the zoom objects, the graphic components, and the autocorrect list, from your outline and the transcript JSON. It cannot watch the video; it reads subs*.json and, if needed, frames extracted with ffmpeg. Mechanical decisions it makes; creative ones you make in the Studio.
Net: one local speech model for captions, one coding agent for the edit, and everything in between is ordinary TypeScript. That is the "nothing faked" property carried into the video tooling: the render is an artefact of code you can read.

8The loop, once per video

What a session looks like once the pieces above exist.

  1. Outline — bullets per pipeline stage, in video/<app>/outline.md. Claude generates any graphics components the outline needs, before recording, so you can show them on screen too.
  2. Record — bun run dev, localhost:4000, one scene per stage, "Use this take". Whisper runs as you go.
  3. Edit as data — Claude reads the subs*.json files and the outline and writes the scene list: chapters, trims, zooms, tradeoff cards. Commits it to Root.tsx.
  4. Review in Studio — localhost:3000. Scrub, adjust x/y on a zoom, delete a card, in the sidebar form. Instant, because previews are single frames.
  5. Render — bunx remotion render <app>. Go make coffee. Upload the mp4 and the .srt.

Tradeoff stated once: step 5 is slower than any GUI editor's export and step 3 is a capability no GUI editor has. For a series where the same shape of video repeats ten times, the second outweighs the first from video two onward.
